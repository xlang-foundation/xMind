# Native A2A message admission

The C++ `POST /a2a` adapter now implements nonblocking text `message/send` using the shared agent executor and embedded-xlang3 repository. The reference remains [A2A 0.3.0](https://a2a-protocol.org/v0.3.0/specification/). This component does not establish full A2A compliance, remote authorization or SDK interoperability.

```json
{"jsonrpc":"2.0","id":"request-1","method":"message/send","params":{"message":{"kind":"message","role":"user","messageId":"client-message-1","parts":[{"kind":"text","text":"Explain this repository"}]},"configuration":{"blocking":false,"historyLength":8}}}
```

Admission uses the server's configured default model. A missing context creates a persisted conversation; a supplied `contextId` must identify an existing conversation. The same one-active-root rule applies as for CLI and editor submissions. The response is the actual current Task, which clients can inspect using `tasks/get`. A new message in a completed task's context creates another task while retaining the prior model conversation. Reusing a task through `taskId` is not implemented yet.

The client message ID is a durable retry identity on the selected server. Context, queued run, user prompt, task-history ownership, mapping and queued event commit in one transaction before a worker is notified. Concurrent and restarted retries reuse the original task; changed text, context or message identity metadata conflicts rather than admitting another execution. A completed retry remains readable even when the server has no configured agent executor. Message IDs are currently server-wide; tenant-scoped identities and authorization remain prerequisites for shared deployment.

Schema version 8 associates newly created messages with their owning execution without changing session history or the agent's conversation input. Positive `historyLength` values up to 256 return the latest actual text user/assistant records from that task. Tool records remain internal. Multiple incoming text parts become a newline-separated prompt; history currently returns that combined text rather than reconstructing input part boundaries or metadata. Older tasks lack provable message ownership: migration preserves their session history and rejects positive task-history requests instead of guessing attribution.

The subsequent [native v1 checkpoint](native-a2a-v1.md) adds blocking sends and version-1 core RPCs. Task continuation, referenced tasks, file/data inputs, push notifications and remote delegation remain incomplete. The [subsequent streaming checkpoint](native-a2a-streaming.md) adds stream/resubscribe and authenticated Agent Card discovery. Unsupported push requests and exhausted blocking/stream capacity fail before admission. Output mode negotiation currently supports `text/plain` only. The existing local-owner authentication and denied browser-origin boundary remain in force.

`native_incoming_repository_contract` tests atomic trigger-fault rollback, changed-input rejection, retry persistence, task isolation and schema-7 migration through xlang3 SQLite. Its explicit lifecycle writes and replies are synthetic storage fixtures. `native_a2a_message_http_contract` uses actual native HTTP, agent workers and storage with an explicitly synthetic Node provider peer to test concurrent retries, model transport, shared context, isolated histories and restart reuse. The isolated Release build passed **47/47 native contracts** with no skips. A subsequent final admission run also passed the added returned-context retry assertion. **60/60 extension contracts** passed.
