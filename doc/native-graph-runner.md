# Native graph execution component

The C++ `GraphRunner` executes immutable backend graph plans through the existing native agent engine and workspace/effect handlers. Source `77ffa610661abdab910b270e086c1bedf9f2a325` passed **41 native and 41 extension contracts** in [isolated CI](https://github.com/xlang-foundation/xMind/actions/runs/37655834894): [hosted CTest](evidence/native-graph-runner-hosted-ctest.log), [original job/TAP](evidence/native-graph-runner-passing-ci-job.log), [hosted provenance](evidence/native-graph-runner-hosted-provenance.json). Earlier local evidence is preserved: [complete build/CTest output](evidence/native-graph-runner-local-build-ctest.log), [source/binary provenance](evidence/native-graph-runner-local-provenance.json). It is a backend component; public graph queue ownership, authenticated HTTP/CLI controls and sidebar graph workflows remain pending. Importing a graph catalog still reports execution unavailable until those services are wired. This component does not establish live-provider or populated-editor acceptance.

Schema version 7 retains each new graph's original task/model input alongside its immutable specification. Legacy roots have an explicitly unavailable input, rather than a guessed prompt reconstructed from session history. Child conversations remain isolated from siblings and root history. Tool children cannot invoke the model engine, and single-agent workers cannot claim graph roots.

The controller admits ready agent/tool nodes with the stored checkpoint revision, runs at most 1–8 workers (default 2), settles actual terminal children from durable records, resolves typed dependency arguments and commits conditional skips. Human steps pause durably after all other runnable branches retire, including a human wait admitted concurrently with executable work. Resume consumes authenticated controller input; completed branches are not replayed. The final root response contains observed node outputs and states, with `source: graph_join`. It does not invent aggregate provider usage.

Direct tools use registered native workspace reads and, when enabled, the existing approved edit/create/process executors. File/command effects retain separate one-use approvals, exact proposals, guidance snapshot preconditions and existing journal/recovery rules. Configured agent nodes retain their model/tool loop, including registered MCP tools. Direct MCP graph-tool aliases remain unsupported.

Cancellation stops and joins owned children before root retirement. Failed effects/children halt later admission. Missing dependency paths retire the root as a data-resolution failure; they do not supply invented values. A persistence fault requests cancellation of other workers and preserves the original fault and unfinished journal for recovery. An effect whose outcome cannot be journaled stays unrecorded/uncertain, even when its actual file bytes exist.

The compiled integration contract uses synthetic provider replies over actual native HTTP transport. It exercises concurrent agent requests, actual file reads, durable human pause/resume, typed references, conditional skips, observed joins, missing files/reference data, cancellation, actual separately approved file creation, cancellation during approval, and an injected SQLite outcome-journal failure followed by recovery without replay. The fixture values are test data, not a live model acceptance result.

Verification output and source/binary provenance belong in `doc/evidence/native-graph-runner-local-*`. The executor currently applies a deadline to each active segment, excluding returned human pauses. A persisted total graph budget, large result artifacts, loop/script nodes, queue ownership and public client integration remain required.
