# Native graph child executions

Release compilation and all **39 native contracts passed locally**: [complete build/CTest output](evidence/native-graph-children-local-build-ctest.log), [source-tree/binary provenance](evidence/native-graph-children-local-provenance.json). The new contract invokes the shared native agent engine concurrently for two graph children. Inference is synthetic; transport, workspace reads, transactions, conversations and reopen are actual. Public graph scheduling/client and live-provider acceptance remain pending.

Repository schema version 5 adds immutable graph root records, parent/node identities on runs and execution identities on messages. Graph admission commits its validated `GraphPlan`, graph identity/revision, initial user message and queued event together. Child admission requires a running graph root and a declared agent node, and atomically commits the child, private prompt, child queued event and identified parent event. An actual failed parent event insert rolls all child admission back. Each root/node identity is unique; repeated loop attempts remain pending.

One active queued/running/paused root is allowed per session. Children share that session's authorization boundary but are excluded from the active-root index and root run listing. Their conversations use execution identities, rather than fake user sessions. Root history excludes child messages. `run_history` selects the appropriate conversation; the shared `AgentRunner` uses it for its normal model/tool loop. It rejects graph roots before claiming them, leaving root ownership to the future graph executor.

Graph pause or terminal transition is blocked while children remain active. Successful graph completion also requires admitted children to have completed. The future coordinator must additionally prove all required/skipped nodes finished; this ledger alone is not a graph scheduling decision. Agent children cannot own human pauses. Cancellation must stop children and observe retirement before retiring the root.

`graph_events` returns committed root/child events in global sequence order with their originating run IDs and cursor filtering. Existing ordinary run event APIs are unchanged. Graph views must group model streams/metrics by child execution. Immutable specifications and isolated histories survive reopen. Existing owner recovery retires interrupted queued/running root and child records, preserves history and retains effect uncertainty/quarantine rules. This layer does not automatically resubmit interrupted children.

The native contract uses an HTTP barrier that replies only after both child agents request inference. Each child invokes the actual `read_file` handler and continues from its file result; the peer verifies that root-private and sibling prompts are absent. It also checks duplicate/competing-root rejection, retirement guards, actual SQLite admission-fault rollback, identified cursors, immutable-spec reopen and interrupted-owner recovery. Older migration fixtures reconstruct their older schemas before downgrading versions; credential/conversation/resource preservation and migration rollback contracts passed in the full suite.

All database I/O remains on the embedded-xlang3 persistence thread. These are internal C++ APIs, with no public manual-completion/state mutation endpoint. Offline graph catalog import still reports `execution_available:false`. Coordinator checkpoint/admission transactions, worker scheduling, tool/human dispatch, authenticated resume, artifacts, cancellation/reconciliation, graph HTTP/CLI/sidebar workflows, bounded-loop attempts and A2A/script types remain required. The full platform/parity goal stays incomplete.
