# Graph workflows in the right sidebar

The VS Code view uses the shared native graph API. The extension remains an access/view adapter: it does not execute plans, invoke models or tools, write workspace files, select controller actors, or set lifecycle states.

When `/v1/graphs` advertises registered workflows, a **Workflow** selector appears above the bottom composer. **Single agent** retains the existing chat path. Selecting an executable graph sends the chosen backend catalog revision and the user's task to `/v1/graph-runs`. A model-free server can advertise actual tool/human graphs. Unavailable graphs remain labeled unavailable; the view does not create placeholder plans or manually entered graph IDs. Older servers returning 404 for the graph catalog keep the existing single-agent view.

The selected root displays node identities, kinds and persisted states. Waiting human nodes show their backend prompts and a JSON input form. Input is submitted with the displayed checkpoint revision; the host verifies the selected root, waiting node and revision, and the backend enforces its authoritative transaction. The raw JSON text reaches native validation unchanged, so duplicate keys are rejected. Draft input survives observation refreshes; completion/selection clears obsolete forms. Changing conversation or run invalidates queued input immediately. Human input supplies data and never grants file, command or MCP effects.

Each agent child displays its isolated backend transcript with the existing Markdown renderer and per-response provider usage/model/timing fields. Live events stream into the corresponding child card; they never masquerade as a root response. Root joins retain observed node outputs without fabricated aggregate usage. Tool outputs appear under the owning node. File/command/MCP approvals use the existing exact proposal review and shared decision endpoints, with the owning node identified. Child operations are accepted only while they belong to the selected graph; root cancellation remains the control path for stopping owned children.

Local verification passed **58 extension client/host/DOM contracts** ([output](evidence/vscode-graph-workflow-tests.log)), **seven compiled native access regressions** ([output](evidence/vscode-graph-native-access-ctest.log)), and a compiled graph service contract that uses the production extension `BackendClient` against real C++ HTTP/xlang3 persistence ([output](evidence/vscode-graph-client-integration-ctest.log)). It checks actual catalog discovery, raw invalid-input rejection with unchanged checkpoints, separately owned child histories, actual workspace effects and provider child usage from a synthetic protocol peer. Host/DOM fixture responses are explicitly synthetic; these tests do not prove a populated IDE or live-provider graph execution.

The user's existing IDE/configuration dialog is preserved. The installed preview remains the older verified native discovery backend, which has no public graph routes; it therefore does not yet expose workflow choices. Installing the graph-capable backend and checking a real graph in the actual IDE remain required. Hosted CI status and exact source/binary provenance must be recorded separately before claiming a hosted or installed checkpoint.

General platform gaps remain: shared/team access policies, PostgreSQL, A2A execution, complete OpenCode parity, loop/script nodes, large result artifacts, total graph budgets and combined scheduling fairness. This adapter does not close those gaps.
