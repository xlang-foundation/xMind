# Native Responses provider

The shared C++ model boundary now includes an explicit Responses wire alongside Chat Completions. `complete_model` chooses the backend-configured adapter; single agents and graph agent nodes use that same boundary. No OpenAI SDK, LiteLLM implementation or CPython execution is added. Local native contracts verify the component scope below; live provider support remains unverified.

Configure a startup model with `--model-wire responses --model-endpoint https://api.openai.com/v1/responses --model MODEL_ID`, the appropriate backend credential reference, and explicit supported capabilities. The isolated preview launcher accepts `-ModelWire responses` with its startup model/endpoint. Existing saved-key previews and their Settings dialogs remain unchanged. The current interactive Settings enrollment policy still uses Chat Completions; configurable enrollment across wire families remains required.

Requests use streaming `input` items, flattened native function schemas with explicit `strict: false`, optional `max_output_tokens`, and `store: false`. The adapter retains completed output items, including opaque encrypted reasoning, for stateless continuation and durable conversation replay. Text/refusal and tool-call projections are checked against those items before serialization. A Responses conversation cannot silently switch to Chat Completions and lose its continuation: that serializer rejects the incompatible retained items. General provider routing and conversation conversion remain incomplete.

Plain authored assistant history uses the easy-input `assistant` role with `input_text` content. A refusal from another wire without original Responses output items is explicitly unsupported; the adapter does not fabricate a provider message ID or erase its refusal distinction. Responses-produced refusals retain their original output items.

The decoder verifies SSE/payload event names, ordered sequence numbers, response and output identities, function-call arguments, text/refusal parts and completed output items. It compares `response.completed` against the completed item records. Truncated, incomplete, failed, unsupported and inconsistent streams do not produce executable tool calls. Function names must also belong to the current request's tool catalogue before the agent can dispatch them. Networking uses the existing native certificate/redirect/cancellation/deadline policy, with no automatic retry.

Reasoning summaries are separate `model.reasoning` events; they are not answer text. Completed reasoning items require an opaque stateless continuation value. Raw reasoning-text content is unsupported and rejected. Opaque items are stored in the assistant's durable `provider_items` payload with the ordinary conversation; authenticated owner history can inspect that payload. They are provider-produced conversation data, not API credentials. API keys retain the separate encrypted backend credential store.

Provider `input_tokens` and `output_tokens` map to the existing input/output metrics fields, and actual cached/reasoning token details are retained. The original supplied counts are also retained. No counters, totals, price or timing estimates are invented. Durations and first-token timing are measured by the shared engine.

Graph settlement keeps provider-native continuation items in the child's conversation but excludes them from its dependency output and the root join. Another node receives the actual answer and metrics as graph data, without receiving another conversation's opaque continuation as user text. The graph fixture runs two dependent Responses agents with actual workspace reads and separately retained child usage/continuation records.

The primary protocol references are the official [Responses streaming events](https://developers.openai.com/api/reference/resources/responses/streaming-events), [function calling](https://developers.openai.com/api/docs/guides/function-calling), and [reasoning continuation](https://developers.openai.com/api/docs/guides/reasoning), inspected on 2026-10-07 with the OpenAI Docs skill. The protocol test uses synthetic byte-fragmented streams and malformed variants. The independent Node peer runs the actual server/CLI, workspace read loop and embedded-xlang3 store with synthetic inference/opaque reasoning; it is not live-model evidence.

Final Release verification passed **52/52 native and 60/60 extension contracts**, with no skips, including the final graph projection and authored assistant input shape. Model discovery alone does not establish that every returned ID supports this wire or the requested tools.
