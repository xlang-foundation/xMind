# Native repository guidance

Implementation checkpoint; native compilation and execution are pending hosted CI. The local build guard deferred compilation while an independent xlang3 benchmark was running. Node contract syntax and diff checks passed. This is not a verified runtime milestone yet.

C++ loads the selected workspace's root `AGENTS.md` at each agent run start, between core instructions and the configured server supplement. Before the first provider request it records `agent.repository_instructions` with source path, workspace/file identities, SHA-256 and actual byte count. The metadata event contains no guidance text. The provider receives the actual file text. Missing root guidance produces an empty source list; invalid or inaccessible guidance fails the run before inference.

The native `read_repository_instructions` tool accepts exactly one string field, `directory`. It reads applicable `AGENTS.md` files from workspace root through an existing target directory in parent-to-child order, returning source text and identities/hashes. Its description directs the model to read this before nested work. Each call rereads files, so changes and deletions appear in the next snapshot. A sibling directory's instructions are excluded. Root guidance is fixed within a run; it refreshes at the next run start.

Reads retain verified parent directory handles and open the final file relative to its parent. Directory reparses, linked guidance files, parent traversal, absolute paths, device/stream names and changed workspace identity are rejected. Only a missing final file counts as absent. An unavailable parent, access/share failure, directory named `AGENTS.md`, binary/invalid UTF-8 or NUL-bearing text produces an error. Each file is limited to 16 KiB, total selected text to 32 KiB, and directory depth to 32. The complete root/core/server system instruction text remains bounded at 64 KiB; overflow fails before inference. Multi-file snapshots are sequential verified reads, not an atomic filesystem transaction.

Repository text is model guidance and cannot authorize a native effect. Existing approval, file/executable binding and durable effect rules remain independent. Guidance may be sent to the configured model and retained in scoped tool history; it is not a secret store. Metadata hashes do not archive prior prompt contents.

Contracts use labeled synthetic inference and actual native filesystem/admin/server/CLI/storage behavior. The standalone native contract checks source order, sibling exclusion, real content hashes, changed/deleted files, absent guidance, unsafe paths, junctions, hard links, invalid text, file/aggregate limits and directory entries. The process integration contract checks actual root text in the transmitted request, metadata without text, and continued native effect permissions. These are pending execution for this checkpoint.

Remaining work includes automatic nested scope updates before file effects, a watch/notification policy for changes during a run, named agent presets, global instruction configuration, skills/commands, prompt archives and compaction. Explicit tool discovery does not establish automatic nested instruction enforcement or full OpenCode parity.
