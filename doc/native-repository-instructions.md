# Native repository guidance

Release compilation and all **37 native contracts passed locally**: [complete local build/CTest output](evidence/native-scoped-guidance-local-build-ctest.log), [source-tree/binary provenance](evidence/native-scoped-guidance-local-provenance.json). The original local attempt deferred during an independent xlang3 benchmark; the benchmark then ended and the guarded complete build passed.

C++ loads the selected workspace's root `AGENTS.md` at each agent run start, between core instructions and the configured server supplement. Before the first provider request it records `agent.repository_instructions` with source path, workspace/file identities, SHA-256 and actual byte count. The metadata event contains no guidance text. The provider receives the actual file text. Missing root guidance produces an empty source list; invalid or inaccessible guidance fails the run before inference.

The native `read_repository_instructions` tool accepts exactly one string field, `directory`. It reads applicable `AGENTS.md` files from workspace root through an existing target directory in parent-to-child order, returning source text and identities/hashes. Its description directs the model to read this before nested work. Each call rereads files, so changes and deletions appear in the next snapshot. A sibling directory's instructions are excluded. The automatic per-run context described below refreshes selected guidance before subsequent model requests.

Reads retain verified parent directory handles and open the final file relative to its parent. Directory reparses, linked guidance files, parent traversal, absolute paths, device/stream names and changed workspace identity are rejected. Only a missing final file counts as absent. An unavailable parent, access/share failure, directory named `AGENTS.md`, binary/invalid UTF-8 or NUL-bearing text produces an error. Each file is limited to 16 KiB, total selected text to 32 KiB, and directory depth to 32. The complete root/core/server system instruction text remains bounded at 64 KiB; overflow fails before inference. Multi-file snapshots are sequential verified reads, not an atomic filesystem transaction.

Repository text is model guidance and cannot authorize a native effect. Existing approval, file/executable binding and durable effect rules remain independent. Guidance may be sent to the configured model and retained in scoped tool history; it is not a secret store. Metadata hashes do not archive prior prompt contents.

Contracts use labeled synthetic inference and actual native filesystem/admin/server/CLI/storage behavior. The standalone native contract checks source order, sibling exclusion, real content hashes, changed/deleted files, absent guidance, unsafe paths, junctions, hard links, invalid text, file/aggregate limits and directory entries. The process integration contract checks actual root text in the transmitted request, metadata without text, and continued native effect permissions. These passed locally at the stated synthetic-inference scope.

Per-run automatic scope delivery is now implemented. Before `read_file`, `list_files`, `edit_file`, `create_file` or `run_process` proceeds, C++ reads guidance for the target file's parent, selected directory or command's relative workdir. New/changed/deleted guidance produces `repository_instructions_required` before tool dispatch or approval proposal. All calls in that model-response batch remain deferred. Before the next provider request, C++ refreshes known scopes and rebuilds bounded system context with directory/source order, deduplicated source text and hashes. The model must reconsider and issue a new call. A directory with only already-delivered root guidance needs no extra round. All 37 local native contracts passed, including real same-batch deferral, edit/create effects after delivery and approval, and changed guidance before a subsequent call.

`agent.repository_scope` records actual identities, hashes and byte counts when supplied context changes, without source text. Context supports at most 32 selected scopes, 32 KiB of unique source text and 48 KiB of serialized guidance; the complete core/guidance/server system message remains limited to 64 KiB. Path scope inputs are limited to 4096 bytes. The root start event describes the initial read; current scope events describe later provider context. Guidance is refreshed before each provider request and scoped dispatch check, rather than through a filesystem watcher.

The automatic check establishes delivery before a proposal, not proof that a model complied with prose. Guidance changes while an already-created proposal awaits approval are not yet bound into that proposal or checked at effect dispatch. A command's workdir scope does not discover every path its arguments might access. Opaque MCP tools have no inferred file scope. Those boundaries, named agent presets, global instruction configuration, skills/commands, prompt archives and compaction remain required. This checkpoint does not establish full OpenCode parity.
