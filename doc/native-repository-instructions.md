C++ loads the selected workspace's root `AGENTS.md` at each agent run start, between core instructions and the configured server supplement. Before the first provider request it records `agent.repository_instructions` with source path, workspace/file identities, SHA-256 and actual byte count. The metadata event contains no guidance text. The provider receives the actual file text. Missing root guidance produces an empty source list; invalid or inaccessible guidance fails the run before inference.

The native `read_repository_instructions` tool accepts exactly one string field, `directory`. It reads applicable `AGENTS.md` files from workspace root through an existing target directory in parent-to-child order, returning source text and identities/hashes. Its description directs the model to read this before nested work. Each call rereads files, so changes and deletions appear in the next snapshot. A sibling directory's instructions are excluded. The automatic per-run context described below refreshes selected guidance before subsequent model requests.

Reads retain verified parent directory handles and open the final file relative to its parent. Directory reparses, linked guidance files, parent traversal, absolute paths, device/stream names and changed workspace identity are rejected. Only a missing final file counts as absent. An unavailable parent, access/share failure, directory named `AGENTS.md`, binary/invalid UTF-8 or NUL-bearing text produces an error. Each file is limited to 16 KiB, total selected text to 32 KiB, and directory depth to 32. The complete root/core/server system instruction text remains bounded at 64 KiB; overflow fails before inference. Multi-file snapshots are sequential verified reads, not an atomic filesystem transaction.

Repository text is model guidance and cannot authorize a native effect. Existing approval, file/executable binding and durable effect rules remain independent. Guidance may be sent to the configured model and retained in scoped tool history; it is not a secret store. Metadata hashes do not archive prior prompt contents.

Before the next provider request, C++ refreshes known scopes and rebuilds bounded system context with directory/source order, deduplicated source text and hashes. Before proposing an agent edit, creation or command, C++ captures a backend-only `InstructionPrecondition` from the delivered scope. The durable approval arguments include `repository_guidance` version 1, its directory, ordered source paths, workspace/file identities, hashes and byte counts. Source text is excluded. An empty source list binds the observed absence of guidance in the directory and ancestors. This metadata is capped at 24 KiB. Models cannot supply this field or the native verification callback.

After the one-use approval is claimed and before effect dispatch, the executor rereads the applicable sources and compares their presence, identities and hashes with the captured snapshot. Changed, replaced, added or removed guidance fails the claimed operation with `repository_guidance_changed_or_unavailable_before_effect`, without applying the file plan or launching a child. A changed snapshot returns `repository_instructions_required` to the agent; its next provider request receives fresh guidance. A new model call creates a fresh proposal and requires a fresh approval. Access/read/cancellation failures also retire the claimed operation before dispatch. If recording that outcome fails, the existing fail-stop/claimed-effect recovery rule remains authoritative. Low-level privileged executor callers may omit guidance; the agent orchestration always provides it for these scoped effects.

Actual native HTTP/CLI/storage contracts check changed guidance during edit and creation approval, newly added and removed guidance, preserved target bytes/absence, old proposal retirement, fresh source hashes and a distinct second approval before the actual effect. The command contract checks that changed root guidance retires an approved command without child output or its marker file. The thin sidebar displays the actual bound directory/source hashes, renders markup/control text literally, and disables Allow for malformed binding metadata. It sends only the decision and operation ID; the host continues validating the complete durable review bytes.

The check proves observed snapshot agreement immediately before dispatch, not continuous filesystem immutability or model compliance with prose. Its reads and subsequent effect are separate filesystem operations. A command's workdir scope does not discover every path its arguments might access. Opaque MCP tools have no inferred file scope. Named agent presets, global instruction configuration, skills/commands, prompt archives and compaction remain required. This checkpoint does not establish full OpenCode parity.
