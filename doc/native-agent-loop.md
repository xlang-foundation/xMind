# Native model/tool agent loop

`AgentRunner` is the shared C++ model/tool loop for backend execution workers and future graph nodes. It invokes the configured provider through the native transport, forwards streamed model events to durable storage, executes offered workspace tools and sends their actual results in the next model request. There is no built-in response generator or substitute provider. `AgentService` schedules it through a bounded native worker queue, with HTTP/CLI submission and cancellation when the server has a model configuration.

The settings select an endpoint/model, optional read workspace, optional encrypted credential reference, instructions, turn bound and run deadline. A workspace requires declared model function-call capability. Without a workspace, the same loop handles text-only single-agent requests. Credentials are resolved through the persistence worker into backend-owned secret bytes for each provider request, separate from model messages. `AgentRunner` and its persistence service must outlive their execution calls.

## Durable lifecycle

Starting commits the queued run and user prompt together. Execution claims queued-to-running atomically; a duplicate worker losing that claim does not fail another worker's run. The current read tools validate arguments and workspace boundaries before file access, and persist started/completed/failed events with distinct activity IDs. An assistant tool-call message and every matching tool result commit in one batch. The final answer, completed state and corresponding events also commit together. User messages submitted separately are rejected while a root run is active, preventing concurrent prompt changes during context construction.

Tool denial and input/file errors are genuine error results returned to the provider. Unknown/unoffered tools never execute. Provider failures, incomplete/model-protocol errors and exhausted turns produce failed states; cancellation produces cancelled state. Provider HTTP error events preserve status only, without copying private provider error bodies. Run timeout is distinct from user cancellation and produces `agent_timeout`.

The run deadline is cooperative: it cancels pending native HTTPS operations and is checked between tool operations. Filesystem I/O proceeds at the OS's pace; this is not a hard real-time deadline. Deadline-thread initialization failure is handled as an agent failure. Pauses, external-effect reconciliation and write/shell permissions are not implemented by this loop. Only the three actual read tools are offered.

## Validation scope

The first full Release run passed twelve native contracts. The loop contract was then rerun after adding the run deadline; the final request/loop contracts passed after preserving refusal provenance and handling deadline-thread creation failures. Evidence: [native-agent-loop-final.log](evidence/native-agent-loop-final.log). A subsequent active-owner claim test also passed: [native-agent-claim-final.log](evidence/native-agent-claim-final.log).

The loop test uses an explicitly synthetic inference wire peer plus real filesystem tools and embedded-xlang3 persistence. It verifies model/tool continuation, actual file content in the persisted tool result, encrypted credential resolution without placing the credential in model messages, workspace denial, HTTP failure, cancellation during a pending request, deadline failure, turn bound, rejection of a competing worker while the actual owner is streaming, atomic rollback under injected storage faults and reopening the saved conversation/state. No live model was called and no coding-task success is claimed by the synthetic reply.

Live provider validation requires the selected endpoint/model and privately configured credential. The product still needs actual VS Code UI validation, complete tool permissions/mutations/processes, context compaction, provider families/routing, MCP/A2A and graphs. These remain part of the full project goal.

`AgentService` is a bounded native worker service behind a transport-neutral `RunExecutor`, with configured server/CLI submission and cancellation. The Release build and all fifteen native contracts passed. Tests cover actual workspace reads through HTTP/CLI, encrypted credential reuse, admission limits, cancellation, parallel workers, joined shutdown and restart recovery. Inference peers are explicitly synthetic. Evidence: [native-execution-server-ctest.log](evidence/native-execution-server-ctest.log).

## Pending approved-edit integration

The pending native sources are being submitted to [isolated Windows CI](native-ci.md) for compilation and all nineteen contracts. This avoids competing with the live local benchmark. Until an actual complete run passes, the verified native baseline remains eighteen contracts and these changes remain unverified.

The current worktree adds an `edit_file` model tool behind the backend's explicit `--workspace-edits approved` setting (`-ApprovedEdits` in the native PowerShell launcher). This setting offers the capability; every valid edit still requires its own durable controller decision. Model arguments select path/literal replacement/count only. The executor derives the verified workspace, actual before/after plan and approval payload, then returns actual applied metadata or a denial/stale-content error to the model. Cancellation retires unused permission; uncertain effects stop the run, and an unrecorded outcome leaves the claim for recovery and degrades the owning service.

This integration is unverified. The new compiled-server contract uses synthetic inference with actual files and HTTP/CLI approvals to cover application, denial, stale content, cancellation, continuation and a forced server restart while approval is pending. Its script passes syntax checking, but native build/execution is deferred while an observed xlang3 performance benchmark is live. The last passing native evidence remains eighteen contracts; no new native checkpoint is claimed until the integration builds and runs.

Pending validation also includes a 64-level parser-depth limit for HTTP request bodies and edit arguments, in addition to existing byte limits. Contracts send 10000-level nested inputs and require the specific bounded-parser error without persistent data/proposals or file changes. Their native execution is deferred by the same benchmark guard.

The streamed model decoder now applies the same depth limit and rejects duplicate object fields in both SSE payloads and reconstructed tool arguments, before emitting executable completion. Pending decoder contracts cover deeply nested provider extensions, deeply nested tool arguments and duplicate fields. These source changes have not yet been compiled or executed.

Direct built-in read/list/search invocation now independently rejects duplicate fields and JSON nesting beyond 64 levels. Pending real-filesystem contracts exercise ambiguous duplicate paths/queries and 10000-level arguments, so future native callers cannot bypass the stream decoder's validation by invoking tools directly. Native execution is still deferred.

The worktree also adds configured model IDs behind `/v1/models`, validated per-run selection, explicit streaming-usage capability, and persisted response usage/request-model identity/backend elapsed and first-output timings. All selectable IDs share the operator-configured endpoint/credential; view clients cannot introduce an endpoint or credential. The synthetic compiled-server contract selects a second configured model, rejects an unconfigured ID before prompt persistence, and checks exact provider-reported usage in history. These C++ changes remain unverified until the benchmark guard clears. The fifteen passing UI renderer/host contracts do not establish native compilation or live inference.

Pending recovery inspection: `EditExecutor::inspect_uncertain` verifies an uncertain file edit, its retired owner and the exact runtime workspace, then fingerprints actual bounded raw bytes. It reports same-file before/after/different matches and observation time. Matching bytes do not prove the original effect succeeded; inspection never replays, changes the journal or clears quarantine. Native contracts now cover after-state observation following the real outcome-storage fault/restart, restored before bytes, partial invalid-UTF-8 bytes and wrong-workspace rejection. They await compilation/execution. Attributed resolution, API/CLI/view integration and post-write process-kill recovery remain required.
