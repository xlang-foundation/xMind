# Native model/tool agent loop

`AgentRunner` is the shared C++ model/tool loop for backend execution workers and future graph nodes. It invokes the configured provider through the native transport, forwards streamed model events to durable storage, executes offered workspace tools and sends their actual results in the next model request. There is no built-in response generator or substitute provider. `AgentService` schedules it through a bounded native worker queue, with HTTP/CLI submission and cancellation when the server has a model configuration.

The settings select an endpoint/model, optional read workspace, optional encrypted credential reference, instructions, turn bound and run deadline. A workspace requires declared model function-call capability. Without a workspace, the same loop handles text-only single-agent requests. Credentials are resolved through the persistence worker into backend-owned secret bytes for each provider request, separate from model messages. `AgentRunner` and its persistence service must outlive their execution calls.

## Durable lifecycle

Starting commits the queued run and user prompt together. Execution claims queued-to-running atomically; a duplicate worker losing that claim does not fail another worker's run. The current read tools validate arguments and workspace boundaries before file access, and persist started/completed/failed events with distinct activity IDs. An assistant tool-call message and every matching tool result commit in one batch. The final answer, completed state and corresponding events also commit together. User messages submitted separately are rejected while a root run is active, preventing concurrent prompt changes during context construction.

Tool denial and input/file errors are genuine error results returned to the provider. Unknown/unoffered tools never execute. Provider failures, incomplete/model-protocol errors and exhausted turns produce failed states; cancellation produces cancelled state. Provider HTTP error events preserve status only, without copying private provider error bodies. Run timeout is distinct from user cancellation and produces `agent_timeout`.

The run deadline is cooperative: it cancels pending native HTTPS operations and is checked between tool operations. Filesystem I/O proceeds at the OS's pace; this is not a hard real-time deadline. Deadline-thread initialization failure is handled as an agent failure. Pauses, attributed external-effect resolution and process permissions remain incomplete. The default workspace offers three read tools; explicit approved-edit configuration adds the gated edit tool described below.

## Validation scope

The first full Release run passed twelve native contracts. The loop contract was then rerun after adding the run deadline; the final request/loop contracts passed after preserving refusal provenance and handling deadline-thread creation failures. Evidence: [native-agent-loop-final.log](evidence/native-agent-loop-final.log). A subsequent active-owner claim test also passed: [native-agent-claim-final.log](evidence/native-agent-claim-final.log).

The loop test uses an explicitly synthetic inference wire peer plus real filesystem tools and embedded-xlang3 persistence. It verifies model/tool continuation, actual file content in the persisted tool result, encrypted credential resolution without placing the credential in model messages, workspace denial, HTTP failure, cancellation during a pending request, deadline failure, turn bound, rejection of a competing worker while the actual owner is streaming, atomic rollback under injected storage faults and reopening the saved conversation/state. No live model was called and no coding-task success is claimed by the synthetic reply.

Live provider validation requires the selected endpoint/model and privately configured credential. The product still needs actual VS Code UI validation, complete tool permissions/mutations/processes, context compaction, provider families/routing, MCP/A2A and graphs. These remain part of the full project goal.

`AgentService` is a bounded native worker service behind a transport-neutral `RunExecutor`, with configured server/CLI submission and cancellation. The Release build and all fifteen native contracts passed. Tests cover actual workspace reads through HTTP/CLI, encrypted credential reuse, admission limits, cancellation, parallel workers, joined shutdown and restart recovery. Inference peers are explicitly synthetic. Evidence: [native-execution-server-ctest.log](evidence/native-execution-server-ctest.log).

## Approved edits and response metadata — CI verified

Release compilation and all nineteen native contracts passed in [isolated Windows CI](https://github.com/xlang-foundation/xMind/actions/runs/37595553681), revision `1a3cb44dcbcf91f362c001c9335624d1be80bd3d`. This avoided competing with the live local benchmark. [Full CTest evidence](evidence/native-model-edit-ci-ctest.log) and [exact runtime/toolchain provenance](evidence/native-model-edit-ci-provenance.json) establish this scope. Twenty extension contracts also passed in that run. The running local preview still uses its earlier verified native binary until a newer tested bundle is selected; no live inference is claimed.

`edit_file` is offered behind the backend's explicit `--workspace-edits approved` setting (`-ApprovedEdits` in the native PowerShell launcher). This setting offers the capability; every valid edit still requires its own durable controller decision. Model arguments select path/literal replacement/count only. The executor derives the verified workspace, actual before/after plan and approval payload, then returns actual applied metadata or a denial/stale-content error to the model. Cancellation retires unused permission; uncertain effects stop the run, and an unrecorded outcome leaves the claim for recovery and degrades the owning service.

The compiled-server contract passed with synthetic inference and actual files/HTTP/CLI approvals: application, denial, stale content, cancellation, tool-result continuation and forced restart while approval is pending. Previously completed effects and response metadata survive restart; pending grants cannot be reused. These are real native effects under a synthetic model protocol, not evidence that a live model completed a coding task. A follow-up contract change exercises the selected-model run through the native CLI and awaits its own CI run.

The 64-level parser-depth limits for HTTP bodies and edit arguments passed, in addition to existing byte limits. Contracts send 10000-level nested inputs and require the specific bounded-parser error without persistent data/proposals or file changes.

The streamed model decoder applies the same depth limit and rejects duplicate object fields in SSE payloads and reconstructed tool arguments before executable completion. Its passing contracts cover deeply nested provider extensions, tool arguments and duplicate fields.

Direct read/list/search invocation independently rejects duplicate fields and JSON nesting beyond 64 levels. Passing real-filesystem contracts exercise ambiguous duplicate paths/queries and 10000-level arguments, so native callers cannot bypass stream validation by invoking tools directly.

`/v1/models` advertises configured IDs with validated per-run selection, explicit streaming-usage capability, and persisted response usage/request-model identity/backend elapsed and first-output timings. IDs share the operator-configured endpoint/credential; view clients cannot introduce either. The passing compiled-server contract selects a second model, rejects an unconfigured ID before prompt persistence, checks exact wire-reported usage/timing in history, and verifies unchanged metadata after restart. Usage is supplied by the synthetic provider, never estimated. This does not establish live provider coverage or full model routing.

`EditExecutor::inspect_uncertain` verifies an uncertain edit, its retired owner and exact runtime workspace, then fingerprints bounded raw bytes. It reports same-file before/after/different matches and observation time. Matching bytes do not prove the original effect succeeded; inspection never replays, changes the journal or clears quarantine. Passing native contracts cover after-state observation following a real outcome-storage fault/restart, restored before bytes, partial invalid-UTF-8 bytes and wrong-workspace rejection. Attributed resolution, inspection API/CLI/view integration and post-write process-kill recovery remain required.
