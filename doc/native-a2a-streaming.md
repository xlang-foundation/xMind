# Native A2A discovery and streaming

The native access adapter adds authenticated `GET /.well-known/agent-card.json`, `message/stream` and `tasks/resubscribe` to the existing JSON-RPC `/a2a` endpoint. The card describes the bound loopback URL, bearer authentication and text modes. It advertises streaming and disables push notifications and extended cards; executable agent skills appear only when the configured executor is available. It contains no credentials, workspace paths, model catalog or conversation data.

Each viewer receives an actual Task first, followed by JSON-RPC SSE artifact/status updates. The adapter reads persisted events in batches of at most 128 and waits to drain the final task events before sending a final status. Completed, failed, cancelled and human-input pauses close the interaction stream. A viewer disconnect does not cancel, change ownership or restart the task. Resubscription replays task-local text events from the beginning; clients should replace their previous partial projection with the new snapshot and stream rather than concatenate two subscriptions.

Text and refusal deltas come from the native model event journal. Assistant tool-turn checkpoints start a replacement artifact; the final committed assistant response replaces temporary text and marks the last chunk. Tool calls, arguments, provider error bodies and internal child events are not projected into A2A output. A completed retry starts with its persisted artifact and does not repeat inference. Its final stream status reports the recorded run state.

The local HTTP adapter permits two simultaneous streams, leaving capacity in its four-worker pool for admission, inspection and cancellation. Capacity is reserved before message admission, and failures/disconnects release the reservation. Heartbeat comments keep idle streams writable; stopping the HTTP server interrupts viewers without inventing a terminal task state. These local limits and the owner-token boundary do not establish team-scale deployment or tenant authorization.

The protocol reference remains [A2A 0.3.0](https://a2a-protocol.org/v0.3.0/specification/). The [official JavaScript SDK](https://github.com/a2aproject/a2a-js) is pinned at **1.3.0** under `Native/tests/sdk`, solely as an interoperability peer. Its explicit v0.3 compatibility resolver/transport exercise discovery, a partial stream and task retrieval. This paragraph records the v0.3 streaming checkpoint. The subsequent [native v1 checkpoint](native-a2a-v1.md) adds direct version-1 core RPCs and blocking sends. Continuation, file/data exchange, push, delegation and remote/team authorization remain required work.

The stream contract exercises actual C++ HTTP, agent workers, xlang3 SQLite and a real workspace file read. Provider replies are explicitly synthetic fixtures. It checks partial output before completion, reconnect/backfill without reexecution, capacity before admission, control availability, viewer disconnect isolation, terminal/failure/cancel/pause closure, tool-turn artifact replacement, more than 256 text events, refusal preservation, SDK interoperability and restart. The final isolated Release build passed **48/48 native contracts**, including the expanded streaming and graph shutdown regressions; **60/60 extension contracts** passed with no skips. Final direct task-control/stream peer runs also passed after their diagnostic labels were updated.
