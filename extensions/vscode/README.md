# xMind for VS Code

This thin extension host adapter connects to the native C++ xMind Server. It does not run an agent or access its database inside VS Code. **xMind: Open Workspace** creates/selects sessions, submits prompts, reads durable run events and requests cancellation. **xMind: Ask About Selection** adds selected code to a draft prompt for review before sending.

Start the backend separately with `Tools/agentflow.ps1 -Action Serve -Model MODEL_ID -ModelEndpoint CHAT_COMPLETIONS_URL -ModelTools supported -Workspace YOUR_PROJECT`. Set the server's `XMIND_AUTH_TOKEN` privately. Model credentials are configured on the backend with `XMIND_API_KEY` or a stored credential reference. Set `agentflow.backendUrl` if the port differs. The current server accepts IPv4 loopback HTTP; remote/team access remains pending.

On first connection, enter that server access token in the VS Code password prompt, or run **xMind: Configure Server Token**. The extension stores it under the canonical server origin in VS Code SecretStorage, obtains it for each host request and does not send it to the webview or save it in workspace settings. This uses the official [VS Code secret storage API](https://code.visualstudio.com/api/references/vscode-api#SecretStorage). A server without a configured model supports session inspection but disables prompt submission.

Build a VSIX with `npm install` and `npm run package`, then use **Extensions: Install from VSIX**. The publisher name is local packaging metadata, not a registered Marketplace identity. No Marketplace publication has occurred.

Sessions are shared with CLI and persist on the backend. Closing the panel disconnects observation; accepted execution continues on the server. Reopening restores the selected session and observes its latest run. Terminal runs refresh the persisted conversation. The current native tools read/list/search within the configured workspace; writes, processes and permission decisions remain unimplemented. The extension does not present approval controls for absent backend routes. Diff review, graph inspection and richer coding UI remain required.

Four client/host-controller tests passed, covering authentication, request contracts, native terminal-state handling, token exclusion from view/state messages and disposal during pending history requests. The native HTTP integration contract also passed using this host client against the actual native server with an explicitly synthetic inference peer. Neither proves real VS Code UI behavior or live-model completion. Evidence: [host tests](../../doc/evidence/vscode-native-host.log) and [native integration](../../doc/evidence/native-execution-server-ctest.log). `node tests/backend-smoke.js URL [PROMPT]` requires an independently configured real provider and `XMIND_AUTH_TOKEN` and must pass before claiming live-provider integration.
